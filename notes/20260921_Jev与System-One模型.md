# Jev 与「System One 模型」（TypeSafe AI）

日期：2026-09-21　来源：小红书分享 + 官方文档 / LangChain 博客 / the-decoder 报道

## 一句话

Jev 是 **TypeSafe AI** 的旗舰模型，属于他们提出的 **System One 模型**这一类：**不生成文本**，只针对「状态（state）+ 类型化问题（typed questions）」直接返回**类型化决策**和**校准过的概率/置信度**，让代码能直接分支、排序、路由。

## 它想解决什么

LLM 是为**人**产出文本的；但软件需要的是**判断**。想让模型做"代码要消费的判断"，就得把文本生成系统硬掰成结构化输出、再把结果解析回来 —— 这个 mismatch 就是它切入的点：
> 不生成文本，不解析。

## 技术要点

| 维度 | 内容 |
|---|---|
| 三种原语 | **Choice**（从选项里选，返回 choice + probabilities + confidence）· **Score**（按评分表打分）· **Noul**（一句话是否为真的 0–1 概率） |
| 调用方式 | 一次请求可以**混用多个问题**，并行、彼此独立地对同一 state 评估；**加问题几乎不增加耗时**，也不会"上下文腐坏" |
| 训练方法 | **RLCD**：reinforcement learning for **calibrated** decisions（用强化学习训"校准过的决策"） |
| 接口 | 走自己的 `/systemone` 端点，不是 `/chat/completions` |
| 生态 | LiteLLM passthrough（`typesafe/jev-1.13.0`）；LangChain 的 `TypeSafeClassifier`，以及 `AutoModeMiddleware`（拿它当"工具调用前的风险守门员"） |
| 团队 | CEO **Diogo Almeida**，前 OpenAI 研究员、InstructGPT 论文作者之一 |
| 发布 | 2026-09-16，early access |

## 官方宣称的数字（注意：厂商自测）

- 约 **200× 更快 / 400× 更便宜**（对比同类 LLM 做分类任务）；官网写的是 **193.6× 更快、444.6× 更便宜**，端到端 70–500 ms
- 定价 **$42 / 十亿 input tokens**（$0.042/M，即每百万约 $0.042），**输出免费**

## 冷思考（值得记住的质疑）

1. **结构化输出本身不新鲜** —— OpenAI 的 Structured Outputs / JSON mode 也能返回固定类别，差别只在速度、成本和质量。
2. **评测是自证的**：他们用**自己构造的四个工作流**，并以"其它模型的回答"当**参考答案**，不是独立验证的正确解；评测里也没有 GPT-6 Astra。
3. **能力很窄**：定位是分类/判定类任务，**不替代** LLM 的开放推理与生成 —— 官方自己也说它是"**补充**"：开放任务用大模型，沿途的小判断用 Jev。
4. 值得关注的趋势：**模型分工**（生成/推理 ↔ 快而便宜的判定）、以及"把 harness 里的分类器做成可调用的模型"这件事被开放出来。

## 还没搞懂的

- RLCD 的 reward 到底怎么定义"校准"（准确率与置信度的权衡如何写进目标函数）。
- "System One / System Two"的命名借用认知科学，是实质性的架构差异还是定位话术。
- 校准概率在小样本、分布外输入上还准不准（这是判定类模型的命门）。
